The interface loads. The app does not.

Social Notes—branded NoteDesk in the UI—is meant to turn manual writing and Instagram direct messages into one private note library. The repository is coherent and builds cleanly, but the live backend is stopped, making every meaningful action fail.

01

What the app is supposed to do

ENTRY

Create an account

The browser posts name, email and password. The Go API creates a user, session and CSRF cookie.

CAPTURE A

Write manually

Create, read, edit, delete, search and filter Markdown notes stored in SQLite.

CAPTURE B

Connect Instagram

Register a sender username and receive a one-time verification code.

VERIFY

DM the inbox

Send that code from the sender account to the dedicated Instagram inbox. A signed webhook binds the sender ID.

INGEST

Save later DMs

Future text DMs from that verified sender become Instagram-sourced notes and appear in the library.

The actual live flow stops before step one. Login, registration, profile loading, notes, settings and webhook processing all share the same API process behind nginx. Because nothing listens on port 8104, nginx returns 502.

Why it does not work

P0

The API service cannot start

Startup requires the configured Instagram inbox owner email to already exist in the users table. The database has zero users, so owner resolution returns sql: no rows in result set; log.Fatal exits the whole server.

P1

Bootstrapping has a circular dependency

The owner must be a user before startup, but normal user creation needs the server to be running. A fresh database therefore cannot satisfy the production startup contract through the product’s own public flow.

P0

A public simulation endpoint can mutate real Instagram state

POST /api/integrations/instagram/simulated-dm has no authentication or webhook signature check. Caller-controlled recipient, sender, message ID and text are passed into the production processing path, which can consume verification codes, activate identities or create notes.

P1

Instagram is presented as available while its own gate says disabled

Configuration rejects INSTAGRAM_ENABLED=true and always returns false, yet the API advertises Instagram as available: true. The dashboard simultaneously labels it “Pending Meta feasibility validation.” These are contradictory product states.

P1

Verification trusts possession of a code, not the entered username

The user enters an Instagram username, but account discovery is bypassed and no stable platform ID is known until the DM arrives. Any Instagram account that obtains the active code can become the bound sender, regardless of the username entered in settings.

Unit tests, Svelte diagnostics, frontend build and Go tests all pass. None assert that systemd can boot with the configured database, nginx can reach the service, a public user can register, or a real signed Meta webhook produces a visible note.

04

What works versus what is proven

Implemented and locally checked

  • Session auth, CSRF protection and ownership-scoped CRUD
  • Note search, source filter, sorting and pagination
  • Signed Instagram webhook parser and message deduplication
  • Responsive Svelte interface and static production build
  • Frontend tests, type diagnostics, build and Go tests pass

Not working or not proven live

  • Public registration, login and workspace loading
  • Any public note creation or retrieval
  • Instagram sender verification through Meta
  • Instagram DM → SQLite note → browser rendering
  • Recovery/health alert when the backend repeatedly crashes
05

Shortest safe recovery order

Remove or lock down the simulation endpoint

Do not expose test ingress through the production router. Delete it from production or require an explicit development-only build/runtime gate that cannot be enabled publicly.

Decouple optional Instagram ownership from server boot

Start the core API even when the configured owner is absent. Mark Instagram unavailable with a precise diagnostic instead of terminating auth and notes.

Bootstrap the owner explicitly

Create or select the owner through a one-time, auditable admin step—never by silently inserting a default account or committing credentials.

Make capability reporting truthful

Return Instagram availability from validated runtime configuration and provider readiness; hide or disable connection UI until that state is ready.

Bind sender identity deliberately

Define whether code possession is sufficient. If the entered username matters, verify the sender ID/username with Meta before activation and show the confirmed account.

Require one authenticated public E2E

Verify register → login → create note → reload, then connect sender → signed real webhook → visible Instagram note. Only then call the app READY.
