User Note Search

Search owned notes by title or Markdown content, highlight matches safely, and show the exact heading-bounded sections where content matches occur.

Confirmed product behavior

  • Authenticated, user-owned search only.
  • Scopes: All, Title, and Content.
  • Title results highlight every case-insensitive match.
  • Content results show heading path, bounded excerpt, and highlighted matches.
  • One note may show up to three matching sections, but pagination and totals count notes.
  • Text before the first heading belongs to Introduction.
  • Query and scope persist in the URL for refresh and browser navigation.
  • No result displays no unrelated notes and offers Clear search.

Current implementation evidence

The backend already performs authenticated, escaped substring search over title and Markdown content in store/phase1.go. The API already accepts q, and the Notes page already has a search field. The missing pieces are scope, ranking, section extraction, match ranges, URL state, and result presentation.

The existing page strips Markdown with one broad regex and shows a generic full-note preview; it cannot identify or navigate to a matching section.

API contract

GET /api/notes?q=camera&search_in=all&sort=relevance&page=1

search_in = all | title | content

Ranking: exact title → title prefix → title substring → content-only; ties use recently updated, then ID. Existing no-query browsing remains compatible.

Each result may include title_matches and up to three sections containing heading, heading path, anchor, excerpt, and UTF-8-safe half-open match ranges. No HTML is returned.

Markdown section rules

  • Recognize ATX headings # through ######.
  • A section ends at the next heading of the same or higher level.
  • Nested headings produce hierarchical paths.
  • Ignore heading-like lines inside backtick or tilde fenced code blocks.
  • Use a synthetic Introduction section before the first heading.
  • Keep excerpts within section boundaries and around 180 visible characters.
  • Use one deterministic slug rule for detail heading IDs and result links.

Lock backend behavior

Add failing tests for scopes, ranking, literal wildcard characters, Unicode, note-based pagination, validation, and cross-user isolation.

Extract Markdown sections

Add one small Go file with pure functions for section scanning, heading paths, fenced-code handling, readable excerpts, and match ranges. No Markdown dependency.

Extend storage search

Keep parameterized SQLite LIKE, rank with a small SQL CASE, and parse sections only for notes selected on the current page.

Expose API scope and results

Validate search_in, default to relevance while searching, preserve existing browse defaults, and return plain-text metadata.

Persist frontend URL state

Extend API types, serialize scope, initialize filters from the URL, use explicit form submission, reset pagination on filter changes, and support Back/Forward.

Render safe highlights

Add one minimal highlight component that renders escaped text segments and validated ranges. Add scope selection, section rows, clear search, and responsive states using the existing Notes layout.

Navigate to sections

Add stable IDs to detail headings using one shared slug helper. Search section links open the owned note at its heading. Exact in-section match scrolling is postponed.

Public authenticated E2E

Verify title/content/all scopes, ranking, Markdown boundaries, Unicode and wildcard literals, URL history, fragments, responsive layouts, and two-user isolation. READY requires public authenticated E2E, not local tests alone.

Risks and deliberate cuts

  • Scale: SQLite LIKE first; add FTS5 only after measured need.
  • Markdown: support ATX headings and fenced blocks, not all CommonMark constructs.
  • Offsets: use Unicode-aware rune ranges and validate them before rendering.
  • Navigation: shared slugging prevents search/detail anchor mismatch.

Postponed: fuzzy or semantic search, external search service, saved/history suggestions, tags, full-body highlighting, exact match scrolling, and full CommonMark parsing.
