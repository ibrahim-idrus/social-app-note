Problem and current evidence

User risk

  • The current screen does not clearly ask whether the returned profile is theirs.
  • Add exact username can submit typed text without selecting a search result.
  • There is no explicit Not my account recovery action.

Implemented baseline

+page.svelte already searches and renders matches. phase2.go already receives Instagram ID, username, name, and photo through Business Discovery. The missing piece is enforced confirmation and backend revalidation.

Target flow

1

Search

Enter Instagram username. Loading and errors are announced.

2

Review

Show photo/fallback, display name, exact @username, and profile link.

3

Confirm

Ask “Is this your account?” with explicit Yes and No actions.

4

Verify

Backend rechecks provider ID, then existing DM-code ownership proof continues.

Deliberate scope

Reuse

Existing Business Discovery endpoint, pending identity model, DM verification, and .account-result styles.

Postpone

Instagram OAuth and new persistence. Re-querying the provider on confirmation is the smallest secure change for this flow.

Acceptance criteria

  • Typed username alone never creates an identity.
  • Exact returned photo/fallback, name, username, and profile link appear before confirmation.
  • No/search again saves nothing and allows correction.
  • Yes sends the reviewed provider ID; the backend revalidates before saving.
  • Mismatch saves nothing and issues no verification attempt.
  • Existing DM-code ownership verification remains required.
  • Tests, checks, build, and authenticated public E2E pass.

Implementation gate

This is planning only. Do not implement, deploy, commit, or push until the user explicitly approves implementation. Plan approval alone is not deployment permission.
